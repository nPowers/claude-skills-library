# Document Lifecycle — Groupzer0

## Description
Describes practical document lifecycle stages (creation, review, approval, publication, maintenance) and gives templates, checklists, and automation ideas. Use this skill to design or improve a content workflow for technical docs, policies, or marketing materials.

## Platforms
- Claude Desktop: Supported
- Claude Code: Supported

## Instructions
1. Ask what kind of document (technical, policy, marketing), audience, and publishing platform (wiki, CMS, repo) the user works with.
2. Outline a recommended lifecycle: draft → peer review → editorial review → approval → publish → archive/maintain, and explain responsibilities at each stage.
3. Provide a checklist for each stage (e.g., draft: scope, outline, references; review: accuracy, clarity, compliance; publish: metadata, SEO, access control).
4. Suggest versioning and storage best practices (branching in VCS, semantic versioning or dates, changelogs) and access control patterns.
5. Recommend lightweight automation: templates, pull-request workflows, CI checks (link validation, linting), scheduled reviews/expiration reminders.
6. If the user requests, generate a sample template or a short policy (title, purpose, owner, review cadence) tailored to the document type.
7. Finish with a concise rollout or onboarding checklist for teams adopting the lifecycle.

## Example Usage
- "Help me design a lifecycle for our API docs hosted in a Git repo"
- "Give me a review checklist for a security policy document"
- "How should we version and archive product release notes?"
